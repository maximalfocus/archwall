peerreview 让两家厂商的 AI 一起检查一个仓库。主方（HOST）负责审查，管 git。同伴（PEER）来自另一家，负责改文件。两边来回改，直到都同意仓库做到了它说的事。

**章程。** 每次先写下“完成”是什么意思，依据你的指令和仓库文档，放在临时目录，不进仓库。文档矛盾或没写，就停下问你。

![](charter.svg)

**同伴。** Claude Code 和 Codex CLI 互相审。两者都用不了才换 DeepSeek，报告里写明。

![](peer.svg)

**一轮。** 主方审查、跑检查，同伴修改，主方读真实的 diff、重跑检查、提交。

![](round.svg)

**护栏。** 每个同伴都有 git 防护和 30 分钟时限。裁决那一轮只能读，不能改。

![](rails.svg)

**何时停。** 检查全过，且同伴在中立提问下回答 CONVERGED。至少跑一轮同伴，没有上限。一轮没有进展就停下。

![](verdict.svg)

**落地。** 各轮压成一个提交，开成拉取请求。打标签记下审过的提交，下次只查改动。`~/projects` 下的仓库不做任何 git 写入；`--chat` 参数在临时仓库里审一个想法。

![](deliver.svg)

**越用越好。** `/peerreview-evolve` 把教训写进技能，但要先过宪法这关。没过的直接丢掉，不记日志。

![](evolve.svg)
